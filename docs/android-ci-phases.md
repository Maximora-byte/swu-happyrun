# Android build and runtime evidence phases

This draft separates mandatory build/lint/JUnit/signature/package checks from conditional device runtime steps inside the same job. The same runner keeps remoteQa private TLS material ephemeral; no key or truststore is uploaded to pass between jobs. API matrix build duplication remains deliberately unchanged in this minimal patch.

All push/PR jobs still build. Without the exact existing one-transition authorization, runtime steps are skipped and a bounded runtime-status.json reports authorized=false/runtime_status=not_run. The job may be green for build/static checks; that never means Android device acceptance passed. The summary explicitly says 未执行设备验收. Existing failed software-AVD runs remain historical failures.

An authorized runtime first executes the existing current-UID KVM ACL checker and acceleration check. Any grant, provenance, boot, launch or instrumentation failure fails the job. HAPPYRUN_REQUIRE_KVM=1 forbids falling back to software mode if effective KVM access is absent. The explicitly approved foreground round is bound only to repository Maximora-byte/swu-happyrun, branch dot/android-foreground-agent, a push whose before is 28871b2d599a8ec8335570effb3207d2564639ab and whose after equals GITHUB_SHA, and API31/35 hosted test runners. It does not authorize future transitions or PR events.

After build and signature/package checks, build-provenance.json binds the complete APK set and SHA256 hashes to repository, actual checkout commit/tree, run ID, attempt, job, API matrix and variant. Runtime recomputes all fields and hashes immediately before invoking existing acceptance. Missing/changed/extra APKs, symlinks, missing required variant roles and context mismatch fail closed. Both seal and verify reject a dirty Git checkout, including non-ignored untracked source. APKs remain in the same run/job workspace. Signature identity is checked by the existing build phase and the sealed hashes bind those exact bytes. The remoteQa release-unsigned inspection input remains an unsigned packaging-inspection role, not an installable signed release.

No latest-artifact lookup, cross-run borrowing, CA/key upload or automatic PR evidence substitution is added. A reviewer may associate a successful exact push with a PR only after independently proving full Git tree equality and recording exact run/artifact provenance. Such association is never reported as the PR's own runtime pass and does not silently satisfy runtime branch protection.

Machine statuses are not_run, pending, passed, failed or unknown. An authorized skipped/cancelled/failed runtime is failed, never passed. Report/upload steps preserve diagnosis; they do not use continue-on-error to hide failure. Malformed event JSON fails the gate step and does not enable runtime. Missing gate output (for example after an earlier build failure) yields authorized=null/runtime_status=unknown and a failing report step, never a false not_run decision.
