## 本地最小探针与输入

先由本地验收者确认指定设备及授权状态。只读采集型号、Android/系统版本、ABI、目标包名/版本、ADB serial 的脱敏标识。记录是否已授权而不自动接受权限；账号会话和原始截图留本地私有目录。

运行候选 `doctor --json` 时明确选择 ADB 路径、serial 和目标包名；先查看 `--help`，不要以其他连接设备代替。此检查不应启动跑步或改变位置、传感器、Root、安全设置。仅当实际输出有证据时更新对应能力；命令能执行不表示能力可用。

应用层样本按 [Issue #9](https://github.com/Maximora-byte/swu-happyrun/issues/9) 的请求采集：精确 app 版本、学校规则来源、已脱敏页面/状态、必要的动态点位来源与记录回查表现。缺少样本时保留阻塞，不猜选择器、学校 ID 或坐标。

## 后续路线与安全边界

1. 核实只读连接和应用版本。
2. 对具体能力建立可失败的独立测试，未知能力保持关闭。
3. 有明确授权及样本后实现匹配版本的适配器，再由本地验证。
4. 只有本次记录最终有效才升级到 `record_verified`。

不自动安装 Root、LSPosed、来源未知 APK，不关闭系统保护，不将参考项目或他人设备成功当作本机证据。用户本人完成登录/必要授权；不把密码、token 或原始设备数据提交 Git。无法使用某一通道仅说明该组合的验证结果，不能写成 vivo 或无 Root 永久不支持。
