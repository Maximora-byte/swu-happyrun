# HappyRun 新手使用教程

本教程面向第一次运行本地工作台的用户。先跑通**合成模拟**，不需要手机、MuMu、学校账号或 Root。
产品已通过 [PR #120](https://github.com/Maximora-byte/swu-happyrun/pull/120) 合入 main；准确版本、软件检查和限制见[集成记录](integration-candidate.md)。
本文不提供伪造学校数据、绕过校验或上传运动记录的方法。

## 1. 先知道能做什么

- 本地工作台：启动合成任务、查看进度、请求停止、保存历史、处理未确认任务。
- 服务器与 fake agent：验证调度、HTTP 协议、持久化和恢复，是可选进阶路径。
- MuMu 桌面工具：独立、受限的实际定位工具，需要指定环境、实例和校准，**不是合成模拟的一部分**。
- GPS Locator：[可选离线预览](gps-locator-preview.md)提供路线转换和只读状态检查，不能开始定位或代替 MuMu。
- Android：另有 APK 与远程模拟路径；Python 工作台不需要安装 APK。
- 学校有效记录、第三方小程序实际轨迹与上传仍未验收。`completed` 只代表模拟完成，不是学校认可的 `succeeded`。

历史 RC2/RC3 的实测只适用于报告里的源码与设备版本，不代表你当前安装版本已经实机验收。
旧 native CLI/enrollment 执行门禁仍关闭，不要通过改配置、删除 journal 或恢复旧分支来绕过。

## 2. 选定版本和安装工具

从官方渠道准备 Git、[uv](https://docs.astral.sh/uv/getting-started/installation/) 和 Python。
项目要求 Python 3.11+；新用户可统一选择 Python 3.13，Windows 历史桌面交付也使用它。
这不是宣称旧 Windows/Python 3.11 故障已修复。安装不需要关闭 TLS、改执行策略、管理员权限或 Root。

首次取得源码：

```sh
git clone https://github.com/Maximora-byte/swu-happyrun.git
cd swu-happyrun
git log -1 --format=fuller
git rev-parse HEAD
```

记录最后输出的完整 SHA，并在 GitHub 核对**同一 SHA** 的检查与产物。
需要复现已审核版本时，使用 `git checkout --detach` 后接该完整 SHA，再重新同步依赖；不要把尖括号占位符原样输入。
`main` 会前进，分支名或包版本号不能代替准确 SHA。也不要从不同分支复制“最新文件”拼装。
合并基线 `1431a4f4328659c45a405a0d82b149487c3e84c6` 不是所有后续修订的代称；需要本教程对应的新修订时应核对包含它的提交。

### Windows PowerShell

在源码目录运行：

```powershell
uv --version
uv sync --python 3.13 --frozen --extra server --extra agent
uv run --no-sync python --version
uv run --no-sync swu-happyrun desktop --help
```

uv 可能需要联网取得 Python 或锁定依赖。无需运行虚拟环境激活脚本，也不要为此修改 PowerShell 安全策略。
已有离线包时可按[桌面指南](desktop.md)双击 `Start-HappyRun.cmd`；旧包不是当前 main 的新构建，先核对来源与摘要。

### Linux

同样在源码目录运行：

```sh
uv --version
uv sync --python 3.13 --frozen --extra server --extra agent
uv run --no-sync python --version
uv run --no-sync swu-happyrun desktop --help
```

Linux 可以运行合成工作台与服务器，但不能据此使用 Windows 专属 MuMu 工具。
交互工作台需要本机可用浏览器；无图形服务器请选第 6 节的服务路径，不要把工作台端口暴露到公网。

## 3. 打开工作台，完成第一次模拟

```sh
uv run --no-sync swu-happyrun desktop
```

保留这个终端。启动器成功监听后会自动打开本机浏览器，默认地址是 `http://127.0.0.1:8765/desktop/`。
首次会话由启动器打开的页面建立；只复制终端里的裸地址，不能代替首次登录引导。
不要分享自动打开页面的原始链接、Cookie 或浏览器调试信息。

1. 等待“控制服务：运行正常”和“本地执行代理：已连接”。
2. 在合成模拟区点击“开始本地模拟”，不要把 MuMu 区当成同一个入口。
3. 正常情况下，约 22 米的合成路线以 2 m/s 运行，约 12 秒后显示“模拟完成”；负载会影响耗时。
4. 查看任务状态与记录。路线是测试用例，不是西大地图或学校正式规则。
5. 再次操作前以最新工作台状态为准，不要连点开始或用多个窗口同时下发任务。

本地合成模拟不需要外网服务。这里的“连接中断”通常指浏览器与本机服务失联，不一定是互联网断网。
**页面失联后，“开始”必须保持禁用，直到成功刷新到新的、可执行的工作区状态。**
旧的“代理已连接”字样不能作为继续开始的依据；无任务、代理就绪和服务健康也须由新响应确认。

## 4. 停止、退出与恢复

- 正在运行时点击“请求停止”。先进入等待确认，再由代理停止并回执，不能把请求已接受当作已停止。
- 正常退出：先确认当前任务状态，再在启动终端按 `Ctrl+C` 请求受控退出。
- 关闭浏览器标签页**不等于**关闭服务或停止任务。
- 服务重启后重新执行启动命令，使用启动器建立新浏览器会话；不要靠旧页面继续提交。
- 中断任务可能显示“需要处理”。“确认结束待处理任务”只请求 `stop_only`，不会重跑路线。
- 不确认停止时保留状态与原因，检查服务和代理，不要删数据库、清 journal、改任务状态或建新身份绕过。

合成模拟的停止不等同于 MuMu 厂商队列清空，更不代表恢复了真实 GPS；实际工具边界见第 8 节。

## 5. 数据在哪里，如何保护

默认合成工作区：

| 系统 | 位置 |
| --- | --- |
| Windows | 当前用户 LocalAppData 下的 `HappyRunDesktop`，通常为 `%LOCALAPPDATA%\HappyRunDesktop` |
| Linux | `~/.happyrun-desktop` |

里面包括 `workspace.json`、`profiles/`、`server.sqlite`、`agent.sqlite` 和 `fake-state.json`。
它们保存合成身份、任务、执行意图和模拟状态，不是可以随便清理的缓存。
Windows 首次创建本人专用受保护目录；Linux 目录必须是私有权限。已有目录权限不合格会拒绝启动，而不是自动放宽。

需另建合成工作区时，`desktop --data-dir` 接一个私有目录路径；父目录须已存在，路径不要使用符号链接。
另一个合成工作区不会改变 MuMu 的实例绑定、独立 journal 或恢复义务。
备份前停止相关服务并确认任务状态，保留一致的数据库文件集与 journal；不要只复制活动数据库主文件。
账号、token、数据库、journal、截图及原始诊断资料不提交 Git、不发群聊、不放进公开 issue。

## 6. 可选：服务器与 agent

如果只想使用工作台，可以跳过本节。工作台已经管理自己的本地服务和 fake agent，不必额外再启动一套。
开发者可先验证临时回环 HTTP 流程：

```sh
uv run --no-sync python deploy/smoke_fake.py
```

脚本使用独立测试身份与临时服务，验证模拟任务及数据库重启后的持久化；只有本次成功才算本次检查通过。
它不连接真实设备，也不产生学校成绩。详细流程见 [fake 联调](fake-e2e.md)。

自管服务先阅读[服务器配置](server.md)，私下配置互不相同的 ADMIN/AGENT token，并注册 agent/device 的 UUID 归属。
不要把凭证放在 URL 或命令行参数中。可先检查实际参数，不会因此启动服务或领取任务：

```sh
uv run --no-sync swu-happyrun server --help
uv run --no-sync swu-happyrun agent --help
uv run --no-sync swu-happyrun devices register --help
```

服务使用 `server --database` 指向仓库外私有数据库，保持单进程、单调度器、回环监听。
控制台地址为 `http://127.0.0.1:8080/console/`（按实际端口）；它与桌面会话是不同鉴权入口。
代理选择 `--backend fake`，配置已注册 UUID、profiles 和私有 journal；不能只填写任意身份就获得设备所有权。
远程连接必须有可信 HTTPS；不要关闭证书校验或公开 ADB/MuMu 端口。完整命令与部署边界见[安装说明](installation.md)。

## 7. 常见问题

| 现象 | 安全处理方式 |
| --- | --- |
| `uv` 或 Python 不存在 | 检查官方安装与当前终端 PATH，重开终端；不要下载来历不明的一键修复脚本。 |
| 缺少 server/agent 依赖 | 回源码目录重跑第 2 节的 `uv sync`；运行时使用同一环境。 |
| 8765 端口已占用 | 已有自己的工作台时复用，或受控停止后再启动。只有端口被其他程序占用、且确认该工作区没有运行实例时，才用 `uv run --no-sync swu-happyrun desktop --port 8766` 换端口。换端口不会隔离数据库或 journal；不要对同一工作区并行启动多个实例，也不要盲杀进程。 |
| 浏览器未打开或首次访问被拒绝 | 确认默认浏览器可用，退出本次服务后重新启动引导；`--no-browser` 不会提供新浏览器的首次会话。 |
| 连接中断，“开始”灰色 | 保留禁用，恢复本机服务/会话并等待成功刷新；不要手动改页面来启用按钮。 |
| 服务正常但代理未连接 | 看终端固定错误码与任务状态，确认同一工作区；不要重复创建任务。 |
| `database_busy` / 503 | 检查重复服务、正在写入的进程和磁盘；等待下一次读刷新，不盲重放创建/取消请求，不删除数据库。 |
| 工作区损坏、链接或权限错误 | 保留原文件并记录错误码，检查私有目录；不要重置身份或放宽权限绕过检查。 |
| 模拟完成但没有学校记录 | 这是预期边界，模拟不是学校业务；不要修改结果或生成假记录。 |

提交问题时提供完整 SHA、系统/Python 版本、命令名、固定错误码与脱敏复现步骤，不附凭证或原始私有数据库。

## 8. 启用 MuMu 轨迹定位

这是**实际位置写入**，不是下方合成模拟按钮，也不是开启旧 native CLI/enrollment 门禁。无需 Root 或 Xposed；没有额外的“全局定位开关”，启用走连接、导入、校准、显式启动流程。
**作用范围是选中的 MuMu 实例系统位置，不是只对 HappyRun 生效。** 实例内其他读取系统位置的应用可能受到影响，不能承诺所有应用都会采纳；不要在含个人业务或正在记录运动的实例上随意校准。
以下由你在明确授权的测试实例中操作。本教程更新本身没有执行设备命令。

### 准备探针与实例

1. 使用 Windows，并确认 MuMu **6.8.4.0 / Android 15 API35**。当前工具会拒绝不匹配版本；历史该版本回执仍不代表当前源码已实机验收。
2. 手动启动本人选定的实例，记下多开器中的编号，等待 Android 启动完成。不要默认选第一个实例，也不要靠重命名身份绕过恢复门禁。
3. 使用已核验完整交付包，先运行 `Start-HappyRun.cmd` 建立包内环境，受控关闭后运行 `Install-MuMu-Probe.cmd`，输入目标实例编号。安装的是同一包的 `Android/probe.apk` 和 `Android/probe-test.apk`，不是任意普通 APK/测试包组合。
4. 只有两次安装均明确成功，安装器才授予自身应用普通粗略/精确位置权限并打开页面。签名冲突、超时或输出不明确时停止，不卸载清数据来硬闯。源码检出不等于已有这套交付包；缺少匹配探针或受检交付目录时尚不满足启用门槛，先按[安装指南](mumu-desktop.md#准备与安装)准备，不从旧包随意拼装。
5. 保持实例里的 HappyRun 自身页面在前台开始观察。正常定位前台服务建立后，可切到其他应用核对位置；无需“始终允许”后台定位。首次 GPS 初始化可能需要约 35 秒，等待真实新鲜读回，不以启动完成代替校准。

### 导入路线、校准、启用

1. 打开工作台，在上方“MuMu 轨迹工具”选择并连接该实例。下方“开始本地模拟”不会启用实际定位。
2. 导入自己有来源的私有 `RouteProfile` JSON：最多 2 MB、10000 路点，包含 UUID `route_id`、规范内容 SHA-256 `revision`、`input_crs`（WGS84/GCJ02/BD09）、`source_ref` 和经纬度 `points`。不能任填 revision 或猜校园坐标，格式与摘要算法见[路线指南](mumu-desktop.md#路线与执行)。坐标转换适用范围外会拒绝。
3. 在外部应用**尚未开始记录**时点击“校准位置读回”。工具实际写入路线起点、距起点至少 30 米的第二点，再返回起点；三次均需新鲜读回通过，才开放启动。失败时看原因，不改门禁强行启用。
4. 校准就绪后填写速度 **0.3–8 m/s**、最长时长 **5–1800 秒**，然后显式点击“启动轨迹”。这些是工具限制，不是学校认可的规则。观察路点与实际读回；不是所有坐标基准都能直接叠加显示。
5. 可按需显式“暂停”“继续”“停止发送”。继续仍需身份、预算等检查通过；不因校准曾通过就永久获得执行权限。

观察窗口从校准前启动观察时开始计时，最长 30 分钟，包含校准、就绪等待和暂停，不因继续或重新校准续期。
开始/继续须为剩余播放时间另留 **90 秒收尾预算**；不够时不会发新定位，可缩短请求或显式停止后重新校准。窗口边缘会受控停止，但预算不是系统 I/O 的硬保证。

### 停止到底意味着什么

点击“停止发送”后等待“已确认停止”，它表示本工具的发送线程和在途命令已结束。
**最后写入的 GPS 坐标仍保留；停止不清除最后坐标、不恢复真实 GPS，也不证明 MuMu 厂商队列已清空。** 暂停同样不能当作恢复真实位置。
若中断或写入结果不明，保留 `needs_attention`，使用“显式停止恢复”；恢复可能需要关闭当前匹配实例，不能拿其他实例的关闭代替证据。
私有状态位于 `%LOCALAPPDATA%\HappyRunMuMu`，独立于合成工作区；不要删除 journal、换目录或篡改身份来绕过待处理状态。
本工具不自动操作学校账号或开始/结束/上传第三方运动记录；位置读回成功不等于第三方应用接受，更不等于学校成绩有效。
完整限制和历史版本证据见 [MuMu 工具指南](mumu-desktop.md)。旧 native CLI/enrollment 门禁继续关闭，没有因这份教程而启用。
