# MuMu 轨迹工具：本机操作

这是独立的本地定位工具。它只控制本人明确选择的 MuMu 实例，不启动、操作或上传步道乐跑记录。自身 Android 应用为 **SELF_PROBE**，用于实际位置读回；不需要启用 Root 或 Xposed。学校账号、规则、有效记录及原生执行门禁仍未接入，本页不是设备验收通过报告。

## 准备与安装

1. 保留完整交付文件夹，先运行 `Start-HappyRun.cmd`，让它校验包并创建 `.runtime` 离线运行环境。首次需要本机已有 Python 3.13。完成后可用 Ctrl+C 正常关闭服务，再安装探针。
2. 启动 **MuMu 6.8.4.0 / Android 15（API 35）** 的目标实例，记下 MuMu 多开器中的实例编号，等待 Android 启动完成。本轮不自动启动或切换实例。
3. 双击 `Install-MuMu-Probe.cmd`，在 Python 提示中输入该实例的数字编号。入口先校验 `SHA256SUMS.json`，再使用随包 `.runtime` 安装固定的 `Android/probe.apk`、`Android/probe-test.apk`。两者必须来自同一交付包。
4. 只有两次 `adb install -r` 均明确成功后，才授予自身 `org.happyrun.app` 的普通粗略/精确位置权限并读回确认，然后打开自身页面。不会卸载应用、清数据、修改 AppOps、Root、系统保护或执行策略。安装失败、签名不匹配、输出不明确或超时均立即停止，不自动重试；保留现有应用与数据，先人工核对版本。
5. 开始观察时先保持 **HappyRun 自身页面在实例前台**。工具建立带通知的定位前台服务后，可以切换到其他应用继续读回 GPS；无需授予“始终允许”后台位置权限。Android 15 首次启动后的 GPS 服务初始化可能需要约 35 秒；工具会等待观察窗口和新鲜读回，不把启动完成当作 GPS 校准成功。服务最多保留一个 30 分钟观察窗口和 5 秒清理余量，结束或进程退出后不自动重启。

需要命令行明确指定实例时，在已经校验完整包后运行：

```powershell
& .\.runtime\Scripts\python.exe .\verify_package.py
if ($LASTEXITCODE -ne 0) { throw '交付包校验失败' }
& .\.runtime\Scripts\python.exe .\install_mumu_probe.py --index 5 --open-app
```

编号只接受 1–8 位 ASCII 数字。编号 `5` 是命令示例，必须替换为本人选定的运行实例。安装器不输出 ADB 身份、原始安装输出或私有文件路径。

## 路线与执行

1. 再运行 `Start-HappyRun.cmd`，在工作台上方的“MuMu 轨迹工具”选择并连接实例。下方“开始本地模拟”使用合成设备，是另一条独立流程。
2. 导入本人私下保存的 `RouteProfile` JSON，文件不超过 2 MB、最多 10000 个路点。必须包含 UUID `route_id`、正确的 64 位十六进制 `revision`、明确的 `input_crs`（`WGS84` / `GCJ02` / `BD09`）、有真实来源的 `source_ref` 与经纬度 `points`；不要猜测校园坐标或学校规则。`revision` 是验证后模型去掉顶层 `revision` 字段的规范 JSON SHA-256，可使用已安装包的 `swu_happyrun.core.canonical.profile_revision` 生成，不能随意填值。
3. 点击“校准位置读回”。这一步会向所选实例写入路线中的两个有来源、非对称点，再返回路线起点，三次均等待 Android 新鲜位置读回，通常需要 10–30 秒。用于校准的两点至少相隔 30 米。起点返回或任何误差/关联未通过时不会开放启动。请在外部跑步应用尚未开始记录时完成校准，避免把校准点间的移动记入运动轨迹。
4. 校准就绪后填写速度与最长时长，显式“启动轨迹”。速度范围 0.3–8 m/s、时长 5–1800 秒，这些是工具边界，不代表学校允许的配速或规则。可显式暂停、继续、停止。图中路线来自上传文件；绿色点为实际读回，仅 WGS84 路线直接叠加，其他坐标基准单独显示读回数值。
5. 正常停止要等“已确认停止”：含义是本工具发送线程及在途命令已结束。**最后 GPS 定位保留**，不声称已清除 MuMu 虚拟定位。完成轨迹同样不代表取得有效学校记录。

校准就绪后，可自行切到所需应用核对位置，再显式启动轨迹。HappyRun 只发送 MuMu 定位并持续核对自身读回；外部应用的开始、结束、账号认证与记录结果仍需单独操作和核验。安装微信或乐跑后可能出现其自身的登录、授权和身份认证页面，应由本人完成所需验证，不提供账号给工作台。

## 中断与私有状态

进程中断、未知写入结果或观察失败会保留 `needs_attention`，不自动重跑或上传。使用“显式停止恢复”并等待确认；如果在途命令无法确认，停止恢复可能需要关闭**当前匹配的实例**，不会以关闭其他实例代替停止证据。若实例已关闭，仍可在下拉框选择它检查原会话并确认停止，无需为停止而启动 Android。

MuMu 模式使用固定私有目录 `%LOCALAPPDATA%\HappyRunMuMu`，设备锁和 journal 独立于合成工作区的 `--data-dir`。不可变绑定固定主机 UUID、原身份文件和 MuMu 安装路径；身份丢失不重新生成，更换目录或配置不能绕过未决会话。旧登记、journal 或运行配置出现时需审核迁移；不要删除、覆盖或改名来规避阻塞。旧 writer 在本版保持关闭；当前只检查记录在私有范围文件中的已知默认来源，未声称扫描任意磁盘上的历史自定义目录。

本版实际观察到 6.8.4.0 / API35 的输入符合 BD09→WGS84 关系，因此先将路线规范到 WGS84，再转换为 BD09 输入；仍必须每次两点校准和逐次新鲜读回。转换使用项目已有公式的数学范围（经度 73.66–135.05、纬度 3.86–53.55 的开区间），范围外拒绝执行。该范围不是覆盖或精度承诺。

MuMu 暂停发送后可能不产生新 GPS 回调。稳定窗口核对最后已确认路点、仍存活的观察心跳和 Android 系统保留位置；保留位置不计作新鲜 GPS 样本，也不声称厂商队列为空或已经清除虚拟定位。

路线文件、读回、截图、设备身份和数据库只保存在私有位置，不提交 Git、不经远程地图服务加载。源代码现场已完成定位、暂停继续、停止及中断恢复；交付包的准确版本与最终实测结果见随包验收记录。软件或浏览器 stub 测试不替代设备验收。
