# R4 MuMu composition: host protocol boundary only

This isolated candidate adds `MuMuDriver`, not a working physical backend.
The ordinary constructor exposes backend `mumu` with **no capabilities**.
Binding/preparation/start/tick raise `unsupported_by_candidate`; verification
returns unknown without evidence; stop raises `stop_unconfirmed`. There is no
CLI registration or new wire field/capability. No device, account, Root,
external gateway, formal upload, or third-party implementation was used.

## Explicit synthetic composition

`MuMuDriver.for_synthetic_testing(fake=..., sensors=..., binding_check=...,
clock=..., location=...)` is only for offline acceptance. `FakeDriver` retains
session/fence/profile/route semantics and rejects device-mode binding. Existing
AgentRunner owns job transitions, durable journal, lease, cancellation and
recovery. The seam reports only `backend=fake`, no capabilities, and rejects
backend-supplied valid status/evidence. It is not registered for real work.

R1 `assert_current` supplies read-only freshness/identity checks. R2 location
uses its original immutable calibration binding, not a replacement observation;
its target/readback remains synthetic. Each location and sensor write invokes
the execution guard again. The synthetic sensor scalar is elapsed test time,
not a pedometer sample, real sensor command, or school-rule implementation.
The protocol suite includes actual R1 binding and R2 calibration/location,
as well as boot-change rejection between location and sensor writes.

Controlled stop attempts all supplied channels even if another channel fails.
Every R2 channel requires exact device-queue confirmation; a local route stop
cannot substitute for it. Any unconfirmed channel raises `stop_unconfirmed`,
preventing stop-ack and preventing completion. Stop does not require the expired
execution guard and never calls `BudaoAdapter.finish()`.

R3 remains rejection-only with its real version registry empty. It is an
explicitly blocked future dependency, not activated through a generic adapter
or fake status string. There is no upload method or implicit finish step. A
future sample-backed implementation must supply version/rule/identity binding,
real bounded transport/readback, and an explicit persisted upload-intent path.
Neither this seam nor a generic finish call can provide that authorization.

## Acceptance evidence and exclusions

`tests/integration/test_mumu_driver_protocol.py` uses the unchanged actual
AgentRunner, ControlClient, server and SQLite journal, synthetic transports and
clock, with actual loopback TCP sockets. Checks include read-only prepare,
accepted running and separately reopened durable start intent before action,
running response loss, stale authority, cancellation, lease expiry, loss of
renewal, old start intent, lower-fence binding rejection, verify-only recovery,
unconfirmed stop, and suppression of synthetic physical capabilities/records.
A successful normal synthetic job can reach completed, never succeeded.

See the adjacent delivery manifest/report for exact commands, hashes, counts,
and any execution restrictions. Passing host tests establishes no real MuMu,
Android, app UI, coordinate mapping, sensor acceptance or school record result.
